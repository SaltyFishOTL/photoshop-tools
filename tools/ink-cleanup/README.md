# Ink Cleanup — Photoshop 全颜色碎点清理

Windows x64 原生 Photoshop 滤镜，当前版本 0.11.0。自动识别不同颜色的孤立碎点，用周边颜色修补；使用 C++ 引擎和预览缓存，并提供精细识别开关。

## 下载与安装

从 [Releases](https://github.com/SaltyFishOTL/photoshop-tools/releases/latest) 下载 ZIP 并解压。

1. 保存工作并关闭 Photoshop。
2. 在 Photoshop 安装目录的 Plug-ins 文件夹中新建 InkCleanup 文件夹，放入 InkCleanup.8bf。更新时先把旧文件备份到 Plug-ins 目录之外，避免重复加载。
3. 启动 Photoshop，打开 RGB、8 位/通道的图片。
4. 选择 **滤镜 → Ink Cleanup → All Color Cleanup…**。

当前版本面向 Photoshop 2025 / 26.8，Windows x64；不支持 macOS。其他 Photoshop 版本尚未验证。

## 使用

- **识别强度**：默认 60；提高后可识别更弱的颜色差异，也可能去掉更多画面细节。
- **最大面积**：默认 60 像素；限制候选碎点的面积。
- **精细识别（较慢）**：默认关闭。开启后，补充检查实际封闭的小区域，用于清理紧邻高光的独立浅点、暗点和彩色点；同时加强细长线条保护。
- 在预览中拖动画面，使用 100% 或更高倍率检查细节，切换清理前后比较。
- 对当前图层处理；有选区时只写入选区内。保留透明度。
- 确定后使用 Photoshop 的撤销操作回退。滤镜实现了参数记录与重放接口；具体智能滤镜宿主行为仍需在目标 PS 环境验证。

自动清理无法理解纹身、装饰纹样与杂点的语义区别，建议保留原图层。

## 0.9 性能与验证

本机相同 1024 × 1024 测试图，独立计算程序耗时从 0.8 的约 33.7 秒降至 0.9 的约 0.51 秒，约 66 倍；结果逐字节一致。此数字包含程序启动和文件读写，不代表 Photoshop 内的完整操作耗时。

另外通过 24 组确定性测试，覆盖颜色、渐变、弱线条、透明度、图像边缘及参数范围，并验证分块缓存、取消和宿主接口。测试用用户原图不随仓库分发。

## 从源码构建

需要 Windows、Visual Studio 2022 C++ 桌面开发工具及 Windows SDK、CMake 3.20+、Node.js。

单独取得 [Adobe Photoshop C++ SDK](https://github.com/AdobeDocs/photoshop-cpp-sdk)，阅读并遵守其许可。SDK 与从其样例生成的资源不包含在本仓库中。

在 VS 开发者命令提示符执行，将 SDK 路径替换为实际位置：

```bat
cmake -S . -B build -G "Visual Studio 17 2022" -A x64 -DPHOTOSHOP_SDK_ROOT="D:/SDK/photoshop-cpp-sdk"
cmake --build build --config Release --parallel 4
node verify-cpp-cases.js
build\Release\cache_test.exe
```

输出滤镜：build/Release/InkCleanup.8bf。构建时 generate.js 从本地 SDK 样例生成 PiPLs.json；不要将生成文件或 SDK 提交到仓库。

engine-native.cpp 是实际清理引擎，auto-engine-0.7.js 仅作为测试参考，不在滤镜运行时执行。filter.cpp / filter.rc 实现原生界面与 Photoshop 接口，preview-cache.h 实现分块缓存。

## 0.10.0：渐变背景上的孤立碎点

保留原检测，再增加局部背景容差 8、最低色差 12 的补充检测，减少底色细微起伏把独立浅点合并为巨大连通区域的问题。对深色碎点同样生效，仍受最大面积和线条连接保护限制；不保证清除贴着主体轮廓的所有碎点。此补充阶段最低色差固定不低于 12，识别强度继续控制原检测。

新增验证：node verify-light-specks.js。覆盖渐变底色上的浅点、暗点，以及长线、大区域、半透明像素保护。24 组参考实现对照、分块缓存及宿主接口测试通过。完整 2048 图本机独立程序测试约 4.4 秒，旧版约 2.9 秒（含读取与诊断输出，非 PS 内实际耗时）。以上改进已包含在工具箱 v1.2.0 中；更新需关闭 Photoshop 后替换 8bf 并重启，不能热更新。


## 0.10.1：深色区域内封闭亮孔

补充即时边界检测，寻找被 RGB 各通道均不高于 32 的深色像素完整包围的小亮孔。仍受最大面积限制，使用八邻域连通，拒绝开放、超面积、涉及透明边界的区域。按实际边界颜色中位数修补；不依赖远处的颜色取样。小型封闭高光与杂点无法仅凭像素语义区分，需在预览中检查。

新增验证：node verify-holes.js。涵盖封闭亮孔、开放亮线、透明边界和超面积保护；在用户提供原图中定位的约 33 像素亮孔已验证清除。用户图片不随源码分发。

## 0.11.0：精细识别

勾选 **精细识别（较慢）**，仍可使用识别强度 60、最大面积 60。关闭后沿用 0.10.1 行为；旧动作中没有新参数时也按关闭处理。预览、动作参数记录及重放均包含新选项。

精细补充阶段在亮度和 RGB 三个通道上，对亮、暗两种方向进行多阈值连通检查。只按实际八邻域像素连接，不跨空隙合并。候选在相邻阈值下需要保持小而稳定，完整的紧邻边界必须与候选有明显色差，再从这圈边界取色修补。旁边另一块高光的距离不会直接决定候选是否合并。

额外限制：最大面积包含扩展后的边缘；拒绝透明边界、超面积区域、明显细长区域，以及无法支持可靠填色的混杂边界。两个阈值相差 16，边界与候选的 RGB 最大通道差至少为 max(12, 16 − 0.2 × 识别强度)，边界颜色与其中位色的最大通道差不超过 32。它仍是像素规则，无法区分同样小而封闭的真实高光和杂点，也不保证清除所有残留点。

修复候选已识别但未成功修补时，仍被旧候选标记阻止精细补查的问题。只有实际写出修补像素的区域才算已处理。

验证：`node verify-precise.js` 覆盖仅隔一像素的大高光旁的浅点、暗点、等亮度彩点、抗锯齿边缘，以及实际连通、对角连接、面积上限、透明像素和细长高光保护。`cache_test` 增加精细开关失效检查及跨分块边界对照；`host_test` 增加旧参数迁移和新参数重放；`ui_test` 检查连续切换选项后应用最新结果及取消。旧模式的 24 组参考对照继续逐字节一致。这些是引擎及模拟宿主验证，不等同于 Photoshop 真机验收。

2026-10-16 在 Photoshop 2025 / 26.8 冷启动后另行通过真机测试：从已注册滤镜入口执行精细处理，临时测试图的小点由灰度 180 修补至周围灰度 70，邻近大高光仍为 180；撤销后小点恢复，缺少新选项的旧参数调用维持普通模式。修复读取旧动作时将新选项当作必填项而返回“模块接口”错误的问题；模拟宿主测试现也检查缺少必填参数的情况。

同机 2048×2048 测试图的独立程序耗时约为普通模式 4.7 秒、精细模式 11.6 秒（包含启动和文件读写，非 PS 内完整耗时）。精细模式会同时保留部分原模式删除的细长区域，所以修补总像素数不一定更多。应在同一位置比较小点与线条，不用总数衡量准确率。
